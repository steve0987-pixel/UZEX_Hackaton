# UZEX — Telegram-агент по локальным данным

Рабочий прототип для предоставленного набора CSV: SQLite, точные десятичные расчёты,
ссылки на файлы и записи, Telegram long polling. Python 3.11+, без pip-зависимостей.
Исходные CSV не меняются. Это **вымышленные данные**, не информация о реальном рынке.

## После клонирования репозитория

Исходные CSV и локальная SQLite-база не включены в Git. Поместите файлы выгрузки
`deals_2022.csv` … `deals_2026.csv`, `contracts.csv`, `participants.csv`, `brokers.csv`
и `usd_rates.csv` в `uzex_spot_data/`, затем выполните импорт по инструкции ниже.
`.env.example` содержит только названия настроек; реальные ключи задаются локально
в `.env`. Файл `miniapp/dist/data.json` содержит опубликованные учебные сводки для
веб-меню, а не полный реестр сделок.

## Запуск

Из корня проекта:

```bash
python3 -m uzex_agent ingest
python3 -m uzex_agent ask 'Оборот за 2025 год'
python3 -m uzex_agent ask 'Сделка 100001'
cp .env.example .env
```

Создайте бота через [@BotFather](https://t.me/BotFather), внесите токен в
`TELEGRAM_BOT_TOKEN` в `.env`. Не отправляйте токен в чат и не коммитьте `.env`.
При необходимости ограничьте доступ через `TELEGRAM_ALLOWED_USERS` (Telegram user IDs).
Затем:

```bash
python3 -m uzex_agent bot
```

Откройте созданного бота, отправьте `/start`. Компьютер с ботом должен оставаться
включённым; для постоянной работы перенесите проект на сервер. Вебхук не нужен.
Один процесс обслуживает запросы последовательно; это прототип, не многопользовательский production-сервис.

## Интерфейс Telegram

### Цветное веб-меню (Mini App)

Опубликованная версия: https://uzex-market-menu.serenebongo16.chatgpt.site
В личном чате с ботом отправьте `/start` и нажмите **✨ Открыть веб-меню**.

В `miniapp/dist` — адаптивное веб-приложение: обзор, годовые отчёты, график по
месяцам, поиск карточек и форма вопроса AI. Числа экспортируются из локальной базы:

```bash
python3 scripts/export_miniapp.py
```

Это фиксированный снимок расчётов, а не онлайн-котировки. Веб-меню показывает точные
суммы в отчётах и сокращённые значения в обзорной карточке. После изменения данных
нужно заново экспортировать и опубликовать `miniapp/dist`.

Для открытия внутри Telegram разместите `miniapp/dist` по доступному HTTPS-адресу,
задайте `MINIAPP_URL=https://...` в `.env` и перезапустите бота. После `/start`
появится кнопка **✨ Открыть веб-меню**. Она открывает приложение из клавиатуры
личного чата, чтобы работал `Telegram.WebApp.sendData`. Не заменяйте её кнопкой
BotFather Menu Button: для такого способа запуска требуется другой backend-поток.

Отчёт можно посмотреть в приложении и запросить в чат. Поиск и AI передают запрос
боту, который заново проверяет входные данные и выполняет расчёт. API-ключей,
Telegram-токена и полной базы во фронтенде нет. В обычном браузере приложение
предлагает скопировать команду и отправить её боту.

`/start` или `/menu` открывает постоянную клавиатуру:

- **📊 Обзор** — количество сделок и покрытие выгрузки.
- **📈 Аналитика** — сумма и число сделок, помесячная динамика, топ продавцов,
  состояния сделок. Выберите отчёт и год кнопками; неполные годы ограничены покрытием.
- **🔎 Поиск** — выберите тип записи и отправьте номер, ИНН или код брокера.
- **💬 Задать вопрос** — примеры свободных вопросов к AI.
- **📚 Источники** — файлы, количество записей и даты покрытия.
- **❓ Помощь** — доступные команды, примеры и ограничения.

AI-план имеет кнопки «Рассчитать» и «Отмена». Подтвердить его может только автор
вопроса, один раз в течение 10 минут. Новый вопрос отменяет предыдущий план.
`/cancel` сбрасывает поиск или ожидающий подтверждения вопрос. Старые кнопки после
перезапуска недействительны; откройте `/menu`.

## Свободные вопросы через Groq

Добавьте в `.env`:

```dotenv
GROQ_API_KEY=ваш_ключ
GROQ_MODEL=openai/gpt-oss-120b
AI_PROVIDER=auto
```

При наличии `GROQ_API_KEY` бот автоматически использует Groq. Устанавливать Ollama
в этом случае не нужно. Groq получает текст вопроса и схему разрешённых операций;
CSV и результаты расчётов остаются на компьютере. Шаблонные вопросы не вызывают API.
Используется [Groq Structured Outputs](https://console.groq.com/docs/structured-outputs)
в режиме `strict: false` с обязательной локальной проверкой плана. Для `GROQ_MODEL`
выбирайте модель с поддержкой JSON Schema, например указанную выше.

Проверить разбор без отправки сообщений в Telegram:

```bash
python3 -m uzex_agent ask 'Какова сумма сделок по цементу за 2025 год?'
python3 scripts/check_connections.py
```

Команда покажет предложенный план; в Telegram перед расчётом также нужно подтвердить
понятые фильтры. При смене ключей перезапустите бота. `AI_PROVIDER=groq` или `ollama`
явно выбирает провайдера, `auto` предпочитает настроенный Groq.
`check_connections.py` проверяет токен через `getMe`, наличие вебхука и разбор
тестового вопроса через AI. Он не отправляет сообщения в Telegram и не выводит ключи.

## Альтернатива: локальная AI-модель

Установите [Ollama](https://ollama.com/), загрузите доступную вам модель с поддержкой
структурированного JSON и русского языка. Задайте `AI_PROVIDER=ollama` и её точное имя в `OLLAMA_MODEL`.
Адрес по умолчанию: `http://127.0.0.1:11434`, меняется через `OLLAMA_URL`.
Модель и Ollama не входят в репозиторий. Без настроенного Groq или Ollama работают только шаблоны из `/help`
и явные JSON-запросы `/query`; этот режим не является полноценным AI-разбором.

Модель получает вопрос и схему операций, а не всю базу. Она возвращает ограниченный
JSON-план через [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs).
Бот показывает план и выполняет его после нажатия «Рассчитать». Модель не пишет SQL
и не составляет фактический ответ. Результат форматирует код из строк базы.
Telegram-интеграция использует [официальный Bot API](https://core.telegram.org/bots/api).

Можно спросить, например: «Какова средневзвешенная цена цемента за 2025 год?»
Но точность понимания языка зависит от выбранной модели: проверяйте фильтры.
100% точность произвольного естественного языка не гарантируется. Свободный разбор
на узбекском и английском зависит от языковых возможностей модели; шаблонные ответы — на русском.

## Расчёты и границы

- Количество сделок: число строк после фильтров. По умолчанию аннулированные исключены.
- Сумма сделок: UZS + USD × курс на дату сделки. Это не фактическая выручка/оплата.
- Объём: количество лотов × размер лота; единицы измерения не смешиваются.
- Цена: сумма исходных сумм / сумма объёмов; валюты и единицы разделяются.
  Для экономически осмысленного сравнения уточняйте товар и атрибуты.
- Цены и объёмы сортируются по названиям групп, а не по несопоставимым величинам.
- Суммы рассчитываются Decimal, итоговое отображение округляется до двух знаков.
  `ask --json` сохраняет неокруглённые значения, SQL, параметры и SHA256 файлов.
- Поиск товара — буквальная подстрока без учёта регистра; остальные поля — точное
  совпадение без учёта регистра. Варианты написания товаров/регионов не объединяются.
- Имена компаний не преобразуются в ИНН. Можно посмотреть карточку по ИНН.
- Вопросы о причинах, прогнозах, сроках просрочки и внешних фактах не поддерживаются.
- Срез покрывает 2022-01-03 — 2026-10-30; даты вне покрытия отклоняются.
  Поэтому для неполного 2026 года укажите конечную дату 2026-10-30 через `/query`.
- Каждое сообщение независимо. Последующие «а за прошлый год?» не используют память.
- Источники: файлы, номера CSV-записей (заголовок = 1), примеры сделок.
  Примеры — только несколько строк; агрегаты считаются по всем совпавшим сделкам.
- `/sources` показывает состав выгрузки; `python3 -m uzex_agent sources` также выводит SHA256 файлов. После изменения
  исходных CSV остановите бота и снова выполните `ingest`: автоматической синхронизации нет.

## Расширенные запросы

```bash
python3 -m uzex_agent ask '/query {"action":"analytics","metric":"turnover","group_by":"month","limit":12,"filters":{"product":"цемент","date_from":"2025-01-01","date_to":"2025-12-31"}}' --json
python3 -m uzex_agent ask '/query {"action":"analytics","metric":"count","cancelled":"include","group_by":"status"}'
python3 -m uzex_agent ask '/query {"action":"analytics","metric":"price","filters":{"contract":"100001"}}'
```

Схема плана: `uzex_agent/engine.py`, переменная `SCHEMA`.
`cancelled`: `exclude`, `include`, `only`. `group_by`: `none`, `year`, `month`,
`region`, `category`, `product`, `status`, `seller`, `buyer`, `seller_broker`, `buyer_broker`.
Карточки: `deal`, `contract`, `participant`, `broker` с полем `id`.

## Проверка

```bash
python3 -m unittest discover -s tests -v
python3 scripts/verify_snapshot.py
```

Первый набор проверяет расчёты на небольшом контролируемом CSV-наборе, отказы и
безопасность плана. Второй независимо сверяет агрегаты SQLite с полными исходными CSV.
Живой Telegram и качество конкретной модели проверяются отдельно после настройки токена и Groq/Ollama.

Условия хакатона по https://hackathon.uzex.uz/saralash/?lang=en проверить не удалось
(HTTP 403); соответствие формальным критериям ещё не подтверждено.
